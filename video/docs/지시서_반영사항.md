## B. 지시서 절별 수정안

### 0. 목표와 입력 파일

- `대본_완성본.srt` 행 → 바꿀 문구:
  > 화면 자막과 타이밍의 기준. **한 줄 자막**(혼잣말 예외는 3-3), **영상 시간 기준**(투자 유의 고지 카드 공백이 SRT 안에 들어 있음). 대본 문장 91개 / SRT 자막 117개.
- `대본_완성본.txt` 행 → 바꿀 문구:
  > 파트 구조, `[장면]` 고지 문구, **대본 문장의 기준**(문장 줄 순서 = 장면 코드의 문장 번호). 엔론 사례 없음.
- `narration.mp3` 행 → 바꿀 문구:
  > 내레이션. 있으면 **오디오가 기준 시계**다. 오디오는 고치지 않고, 자막(SRT)과 장면 시간을 오디오의 실제 말소리에 맞춘다(`npm run align-audio`). 자막은 말보다 0.1초 먼저 뜬다.
- 출력에 추가:
  > 3. `input/대본_완성본.srt` — 최종 영상과 같은 시간의 자막 파일 (영상과 함께 전달)

### 1. 절대 규칙

- 4번에 덧붙임:
  > SRT 자막을 이어 붙인 글은 TXT 문장과 글자까지 같아야 한다(`parse-srt` 가 검사, 다르면 멈춤).
- 5번 "어떤 요소도 그 내용을 말하는 자막보다 먼저 나오지 않는다"에 덧붙임:
  > 한 문장이 화면 자막 두 개로 나뉘면, **뒷줄에 나오는 내용의 그림은 뒷줄 자막이 뜰 때** 나온다. (예: "안 그래도 고점에서 내려오던 주가가 그 소식에" → "최대 -26%까지 폭락했다는 거예요." 에서 "-26%"는 뒷줄에)

### 2. 기술 설정과 속도 규칙

- **컴포지션** → 바꿀 문구:
  > 1920×1080, 30fps. 길이 = SRT 마지막 자막 끝 + 여유 1초. 내레이션이 더 길면 내레이션 끝까지 (오디오를 자르지 않는다).
- **타이밍** → 바꿀 문구:
  > 장면의 시작과 끝은 **대본 문장 번호**(TXT 문장 줄 순서, 제목·파트 머리·[장면] 블록 제외)로 계산한다. SRT 번호는 자막을 나누면 바뀌므로 장면 코드에 쓰지 않는다. 한 문장의 k번째 화면 자막 시작은 `line(n, k)`. 초를 하드코딩하지 않는다.
- **투자 유의 사항 카드** → 바꿀 문구:
  > 문장 18이 끝난 직후에 **3.5초** 카드를 넣는다. 이 공백은 **SRT 안에 그대로 있다**(문장 18 마지막 자막 끝 ~ 문장 19 첫 자막 시작). 코드에서 따로 밀지 않는다. 내레이션이 있으면 공백은 녹음의 무음 길이를 따르고, 3.5초보다 짧으면 안 된다. 고지 문구 3줄은 1초 안에 모두 나오게 한다.
- **속도 규칙**에 추가:
  > 내레이션이 없을 때 자막 읽기 속도는 원래 SRT 의 **1.1배**로 한다.
- 오디오 → 새 항목:
  > `@remotion/media` 의 `<Audio>` 로 넣는다. `input/narration.mp3` 를 `public/` 으로 복사하는 준비 단계(`npm run prepare-data`)를 둔다. BGM 은 내레이션보다 -18dB.

### 3-3. 자막 → 바꿀 문구

> - 화면 하단 중앙, 아래 여백 72px, 최대 너비 1500px, 46px Noto Sans KR 700. (띠 색·불투명도는 기존 그대로)
> - **자막은 한 줄씩 보인다.** 원래 두 줄인 자막은
>   - 두 줄을 이어 붙여 **자막 띠 안(글자 폭 1432px 이하, 실제 글꼴로 잼)**에 들어가면 한 줄로 합친다.
>   - 들어가지 않으면 **원래 줄바꿈 위치**에서 자막 두 개로 나눈다. 시간은 글자 수(공백 제외) 비율로 나눈다.
>   - **예외:** "앞의 사연과 같이" 다음의 혼잣말 3개("이 종목은 전망이 좋으니까…", "여러 종목에 나눠 사면…", "혹시 떨어져도…")는 원래 두 줄 그대로.
> - 자막 사이에 빈 화면이 없다(고지 카드 공백만 예외). 등장·퇴장은 4프레임 페이드.

### 3-4. 모션

- "각 요소는 그 내용을 말하는 자막이 시작될 때 등장한다" → 바꿀 문구:
  > 각 요소는 그 내용을 말하는 **화면 자막(줄)**이 시작될 때 등장한다.
- "장면 전환은 … 번갈아 쓴다"에 덧붙임:
  > 장면을 빼서 와이프가 두 번 이어지는 곳(현재 S22 → S24)은 그대로 둔다(파트 경계).

### 4. 데이터 시트

- 엔론 4행 삭제: "엔론 파산", "엔론 직원 퇴직연금 중 자사주 62%", "팔 수 있었던 가격 80·70달러", "퇴직연금 손실 10억 달러 이상" (출처 미 의회조사국·CNN, CNN, Wharton 도 삭제).

### 5. 장면 구성

- 제목 → "자막 번호 기준, 고지 카드 포함 **29장면**"으로. 번호 열은 **대본 문장 번호**로 바꾼다.
- **S23(엔론) 행 삭제.** 장면 번호는 바꾸지 않는다(S22 다음이 S24).
- S24 이후 번호 고치기 (원본 자막 번호 − 5 = 대본 문장 번호):
  | 장면 | 지시서 v2.0 | 대본 문장 번호 |
  |---|---|---|
  | S24 | 60–62 | 55–57 |
  | S25 | 63–68 | 58–63 |
  | S26 | 69–74 | 64–69 |
  | S27 | 75–79 | 70–74 |
  | S28 | 80–84 | 75–79 |
  | S29 | 85–90 | 80–85 |
  | S30 | 91–96 | 86–91 |
  표 안 "자막 64에서 …" 같은 문구도 같은 식으로 −5.
- S11 행: "고지 6초" → "고지 3.5초", 연출 "노랑 띠 카드에 고지 문구 3줄이 1초 안에 순서대로 나타난다".

### 6. 작업 순서

- 3번 → 바꿀 문구:
  > SRT·TXT 를 파싱해 `subtitles.ts` 를 만든다. **대본 문장 91개, SRT 자막 117개(두 줄은 혼잣말 3개뿐), SRT 와 TXT 글자 일치, 고지 공백 3.5초 이상**인지 콘솔에 출력해 확인한다. 전체 길이: 내레이션 없을 때 약 7분 51초, 이번 내레이션 기준 약 8분 6초.
- 3번 뒤에 새 단계:
  > 3-1. 내레이션이 있으면 `npm run align-audio` 로 SRT 를 오디오에 맞추고, 정렬 검증(밀림이 줄지 않는지, 말 길이 / 글자 수 비율, "넘친 만큼 민다" 모델 잔차)을 보고한다.
- 5번 still 이름 → "자막 단위" 를 **"문장 단위"(`S25-61.png` = 문장 61)** 로. index.html 카드에 "문장 n · SRT a–b" 를 쓴다.

### 스토리보드 검수표에 추가

- [ ] 화면 자막이 한 줄인가 (혼잣말 3개만 두 줄)
- [ ] 두 자막으로 나뉜 문장에서, 뒷줄 내용의 그림이 뒷줄 자막과 함께 나오는가
- [ ] SRT 시간 = 영상 시간인가 (고지 카드 공백 포함), 내레이션이 있으면 말소리와 자막 시작이 맞는가

## C. 검수에서 굳어진 해석 (지시서에 적어 두면 다음에 다시 판단하지 않아도 됨)

1. 출처 캡션은 24px 예시 대신 **28px** (최소 글자 28px 규칙 우선).
2. 축소해서 다시 쓰는 카드 안 글자도 **28px 이상** (예: S29 계좌 카드 배율 0.8).
3. ✕ 표시 같은 덧그림은 **아래 글자를 가리지 않게** (S16 "현금 0원").
4. 160px 이상 큰 숫자는 **좌우 여백 96px** 안에 들어가는지 확인 (S25 "-2,000만 원").
5. S03 이후 계좌 카드 머리글은 "내 계좌"만 — 잔고 금액은 데이터 시트에 없어 쓰지 않음.
6. 번개 도형은 잉크색 — 노랑은 화면당 강조 하나에만.

## D. 다음에 피하면 좋은 것

- 이번 내레이션은 SRT 자막 칸보다 길게 읽힌 줄이 쌓여 끝에서 **15.4초** 늦었다(486.5초 vs 영상 471.1초).
  다음에는 **내레이션을 먼저 만들고 → `align-audio` 로 SRT 를 맞추는 순서**로 하거나, 음성 도구에서 SRT 칸 길이에 맞춰 읽게(빠르기 조절) 한다.
- 고지 카드는 녹음의 그 자리 무음이 약 4.76초라(자막이 말 끝 뒤 0.3초 더 남고, 다음 자막이 0.1초 먼저 뜬 뒤) **4.37초**가 됐다.
  정확히 3.5초가 필요하면 녹음에서 그 무음을 약 3.9초(= 3.5 + 0.3 + 0.1)로 맞춘다.
