# 몰빵 영상 모션그래픽 제작 지시사항 (Claude Code용)

버전: v1.0 — 2026-10-05
영상 제목: 한 종목에만 몰빵해서 얻은 천만원 수익이 -3천만원이 됐습니다. 한 종목 올인한 사람들의 최악의 결말

---

## 0. 목표와 입력 파일

**목표:** 대본 내용을 모션그래픽만으로 시각화해서 시청자가 한눈에 이해하는 최고 품질의 Vox 스타일 설명 영상을 만든다.

**입력 파일 (이 폴더에 있음)**
| 파일 | 용도 |
|---|---|
| `대본_완성본.srt` | 자막 텍스트와 타이밍의 기준 (자막 43개, 약 4분 8초) |
| `대본_완성본.txt` | 파트 구조와 `[장면]` 지시 확인용 |
| `narration.mp3` 또는 `narration.wav` (선택) | 내레이션 음성. 있으면 넣고, 없으면 무음으로 만든다 |
| `bgm.mp3` (선택) | 배경음악. 있으면 내레이션보다 -18dB 정도 낮게 깐다 |

**출력:** `out/final_4k.mp4` (3840×2160, 30fps)

## 1. 절대 규칙

1. **이미지를 쓰지 않는다.** 사진, PNG/JPG, AI 생성 이미지, 스톡 영상, 이모지 모두 금지. 모든 시각 요소는 코드로 그린 벡터(SVG, CSS 도형)와 텍스트로만 만든다.
2. **실제 기업 로고를 그리지 않는다.** 기업은 회사명 텍스트(예: META, GOOGL, CDNS, MDB)로 표시한다.
3. **숫자는 4번 데이터 시트의 값만 쓴다.** 새 숫자를 만들지 않는다. 실제 데이터가 아닌 개념 그래프에는 축 눈금 숫자를 넣지 않고 작은 글씨로 "개념도"라고 표시한다.
4. **자막 문장은 SRT 그대로 쓴다.** 대본 내용을 바꾸거나 추가하지 않는다.
5. **화면 텍스트는 핵심 키워드와 숫자만** 쓴다. 자막 문장을 화면에 그대로 반복하지 않는다.
6. **수익은 빨강, 손실은 파랑**으로 통일한다. (국내 증권 앱 관례)
7. **한 화면에 한 메시지.** 모든 애니메이션은 해당 자막 내용을 이해시키는 목적이 있어야 한다. 장식용 움직임은 넣지 않는다.
8. 그래픽은 자막 영역(화면 하단)을 침범하지 않는다.
9. 모르는 값(예: 채널명)은 변수로 두고 작업을 멈추지 않는다. 마지막 보고에서 알린다.

## 2. 기술 설정

- **프레임워크:** Remotion (React + TypeScript, blank 템플릿). 프로젝트는 `./video` 폴더에 만든다.
- **Remotion Agent Skills 설치:** `npx skills add remotion-dev/skills` (Remotion 공식 스킬. 작업 전에 설치하고 따른다)
- **컴포지션:** 1920×1080, 30fps. 길이 = SRT 마지막 자막 끝 + 고지 카드 3초 + 여유 1초.
- **폰트:** `@remotion/google-fonts`로 로드한다.
  - Noto Sans KR (500, 700, 900): 본문, 숫자, 자막
  - Noto Serif KR (700, 900): 장면 헤드라인
  - 숫자는 `font-variant-numeric: tabular-nums`로 카운터가 흔들리지 않게 한다.
- **타이밍:** 모든 장면의 시작과 끝은 SRT 자막 번호로 계산한다. (프레임 = 초 × 30, 반올림) 초를 직접 하드코딩하지 않는다.
- **투자 권유 고지 카드:** 자막 19번이 끝난 직후(01:38.63)에 3초짜리 카드를 넣는다. 자막 20번 이후는 모두 3초 뒤로 민다. 내레이션 파일이 있으면 같은 지점에서 오디오를 나누고, 뒷부분을 3초 뒤로 민다.
- **최종 렌더:** `npx remotion render <컴포지션ID> out/final_4k.mp4 --scale=2 --codec=h264 --crf=16`
- **폴더 구조 (권장)**
  ```
  video/src/data/subtitles.ts   ← SRT 파싱 결과
  video/src/data/facts.ts       ← 4번 데이터 시트
  video/src/design/             ← 색, 폰트, 모션 상수
  video/src/components/         ← 공통 컴포넌트
  video/src/scenes/S01.tsx ~ S24.tsx
  video/src/Video.tsx
  ```
- 수정할 때마다 `CHANGELOG.md`에 버전, 날짜, 바뀐 장면을 기록한다.

### 3-1. 색상

|---|---|

### 3-2. 배경과 질감
- 크림 배경 위에 SVG `feTurbulence` 노이즈로 만든 종이 질감을 6% 정도로 얹고, 가장자리에 아주 약한 비네팅을 준다.
- 위기 장면(S05~S08)은 다크 네이비 배경을 쓴다.
- Vox 느낌을 위해 찢어진 종이 가장자리(불규칙 폴리곤 clipPath), 손으로 그린 듯한 마커 동그라미와 밑줄(약간 흔들리는 path)을 코드로 그린다.

### 3-3. 타이포그래피 (1080p 기준)
| 요소 | 크기 | 폰트 |
|---|---|---|
| 강조 숫자 | 160–240px | Noto Sans KR 900 |
| 장면 헤드라인 | 72–96px | Noto Serif KR 900 |
| 라벨 | 36–44px | Noto Sans KR 700 |
| 출처 캡션 | 22px | Noto Sans KR 500, 웜 그레이 |
| 자막 | 46px | Noto Sans KR 700 |

### 3-4. 자막
- 화면 하단 중앙, 아래 여백 80px, 최대 너비 1500px.
- 크림 배경 장면: 잉크 글자 + 크림색 띠(#F2EBDD, 불투명도 90%, 모서리 12px).
- 네이비 배경 장면: 흰 글자 + 네이비 띠(불투명도 80%).
- SRT의 줄바꿈을 그대로 쓰고, 자막 하나에 한 문장만 보이게 한다.
- 등장과 퇴장은 4프레임 페이드로 하고, 자막 사이에 빈 화면이 생기지 않게 한다.
- 그래픽은 세로 820px 위쪽에만 배치한다.

### 3-5. 모션 원칙
- 등장 12–18프레임, 퇴장 8–10프레임. spring 기반 ease-out을 쓰고, 과한 바운스는 넣지 않는다.
- 여러 요소는 4–6프레임 간격으로 순차 등장한다.
- 장면마다 카메라를 1.00 → 1.04로 천천히 줌인하고, 배경·중간·전경 레이어에 패럴랙스를 준다.
- 핵심 단어와 숫자는 뒤에서 노랑 형광펜이 왼쪽에서 오른쪽으로 10프레임 동안 그어지며 강조된다.
- 선과 차트는 `stroke-dashoffset`으로 그려지는 애니메이션을 쓴다.
- 금액과 %는 20–30프레임 동안 카운트업 또는 카운트다운한다.
- 장면 전환은 찢어진 종이 와이프와 컷을 번갈아 쓴다.
- 핵심 정보는 해당 자막이 시작될 때 등장하게 맞춘다.

## 6. 작업 순서

1. 입력 파일을 확인한다. SRT나 TXT가 없으면 멈추고 알린다.
2. `./video`에 Remotion 프로젝트를 만들고 Agent Skills를 설치한다.
3. SRT를 파싱해 `subtitles.ts`를 만들고, 고지 카드 3초를 반영한 전체 길이를 콘솔에 출력한다.
4. 디자인 시스템(색, 폰트, 배경 질감, 자막, 형광펜, 카운터, 선 그리기, 와플 차트, 종이 와이프)을 공통 컴포넌트로 만든다.
5. S01–S24를 구현한다.
6. **검수:** 장면마다 대표 프레임 2장을 `out/stills/`에 still로 렌더해서 직접 열어 확인하고 고친다.
   - 글자 잘림, 겹침, 자막 영역 침범이 없는가
   - 화면 숫자가 데이터 시트와 일치하는가
   - 이미지·이모지·로고를 쓰지 않았는가
   - 각 장면이 해당 자막과 같은 시간에 나오는가
   - 수익은 빨강, 손실은 파랑인가
7. 1080p 미리보기(`out/preview_1080p.mp4`)를 렌더해서 전체 흐름을 확인한 뒤, 최종 4K를 렌더한다.
8. **결과 보고:** 출력 파일 경로, 영상 길이, 장면별 한 줄 요약, 사용자가 채워야 할 값(채널명 등)을 알린다.
