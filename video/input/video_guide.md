# 몰빵 영상 모션그래픽 제작 지시사항 (Claude Code용)

버전: v2.0 — 2026-10-06 — 최신 대본(자막 96개, 약 9분) 기준으로 전면 개정, 스토리보드 승인 단계·장면 적합성 규칙·렌더 속도 규칙 추가

영상 제목: 한 종목에만 몰빵해서 얻은 천만원 수익이 -2천만원이 됐습니다. 한 종목 올인한 사람들의 최악의 결말

## 0. 목표와 입력 파일

**목표:** 주식을 시작한 지 얼마 안 됐고 손실을 본 시청자가, 자막을 읽는 동시에 화면만 봐도 내용이 한눈에 이해되는 고품질 Vox 스타일 설명 영상을 만든다. 단, 제작과 렌더에 시간이 과하게 들지 않게 한다.

**입력 파일 (이 폴더에 있음)**
| 파일 | 용도 |
|---|---|
| `대본_완성본.srt` | 자막 텍스트와 타이밍의 기준 (자막 96개, 마지막 자막 끝 09:01.37) |
| `대본_완성본.txt` | 파트 구조와 `[장면]` 화면 고지 문구 확인용 |
| `narration.mp3` 또는 `narration.wav` (선택) | 내레이션. 있으면 넣고, 없으면 무음으로 만든다 |
| `bgm.mp3` (선택) | 배경음악. 있으면 내레이션보다 -18dB 정도 낮게 깐다 |

**출력**
1. `out/storyboard/` — 장면별 샘플 이미지와 확인용 페이지 (**전체 렌더 전에 반드시 먼저 보여 준다**)
2. `out/final_1080p.mp4` — 1920×1080, 30fps (사용자 승인 후 렌더)

## 1. 절대 규칙

1. **이미지를 쓰지 않는다.** 사진, PNG/JPG, AI 생성 이미지, 스톡 영상, 이모지 모두 금지. 모든 시각 요소는 코드로 그린 벡터(SVG, CSS 도형)와 텍스트로만 만든다. 사람 얼굴·인물 그림도 그리지 않는다.
2. **실제 기업 로고를 그리지 않는다.** 기업은 이름 텍스트(예: META, GOOGL, NVDA, MDB)로 표시한다.
3. **숫자는 4번 데이터 시트의 값만 쓴다.** 새 숫자를 만들지 않는다. 실제 데이터가 아닌 개념 그래프는 축 눈금 숫자를 넣지 않고, 구석에 작게 "개념도"라고 쓴다.
4. **자막 문장은 SRT 그대로 쓴다.** 대본 내용을 바꾸거나 추가하지 않는다.
5. **장면 적합성 (가장 중요):** 화면의 모든 요소는 그 순간 나오는 자막의 말을 그림으로 보여 주는 것이어야 한다.
   - 자막에 없는 내용을 화면에 넣지 않는다. 장식용 아이콘, 분위기용 도형, 맥락 없는 효과를 넣지 않는다.
   - 어떤 요소도 그 내용을 말하는 자막보다 먼저 나오지 않는다.
   - 시청자가 "왜 갑자기 이게 나오지?"라고 느낄 만한 요소가 하나라도 있으면 뺀다.
   - 이미 나온 요소를 다시 쓸 때(예: 사연자의 계좌 카드)는 같은 모양·같은 색으로 써서 같은 것임을 알아보게 한다.
6. **화면 텍스트는 핵심 키워드와 숫자만** 쓴다. 자막 문장을 화면에 그대로 반복하지 않는다. 한 화면의 텍스트 덩어리는 3개 이하로 한다.
7. **색의 의미를 영상 전체에서 고정한다.** (3-1 참고) 수익은 빨강, 손실은 파랑이다. 국내 증권 앱 관례를 따른다.
8. **한 화면에 한 메시지.** 그래픽은 자막 영역을 침범하지 않는다.
9. 모르는 값은 변수로 두고 작업을 멈추지 않는다. 마지막 보고에서 알린다.

## 2. 기술 설정과 속도 규칙

- **프레임워크:** Remotion (React + TypeScript, blank 템플릿). 프로젝트는 `./video` 폴더에 만든다. 이미 `./video`가 있으면 새로 만들지 말고 이 지시사항에 맞게 고친다.
- **Remotion Agent Skills:** `npx skills add remotion-dev/skills`로 설치하고 따른다.
- **컴포지션:** 1920×1080, 30fps. 길이 = SRT 마지막 자막 끝 + 고지 카드 6초 + 여유 1초 (약 9분 8초).
- **폰트:** `@remotion/google-fonts`로 Noto Sans KR(500, 700, 900)과 Noto Serif KR(700, 900)을 로드한다. 숫자는 `tabular-nums`.
- **타이밍:** 장면의 시작과 끝은 SRT 자막 번호로 계산한다. 초를 하드코딩하지 않는다.
- **투자 유의 사항 카드:** 자막 18번이 끝난 직후(01:33.29)에 6초짜리 카드를 넣고, 자막 19번 이후는 모두 6초 뒤로 민다. 내레이션 파일이 있으면 같은 지점에서 오디오를 나누고 뒷부분을 6초 뒤로 민다.
- **속도 규칙 (제작·렌더 시간을 줄이기 위해)**
  - 최종 렌더는 1080p 30fps로 한다. 4K는 사용자가 요청할 때만 `--scale=2`로 렌더한다.
  - 프레임마다 계산되는 무거운 효과를 쓰지 않는다. `filter: blur`, SVG `feTurbulence`, 큰 그림자, 큰 요소 전체의 실시간 필터는 금지한다. 종이 질감은 가벼운 CSS 그라데이션이나 고정된 작은 점 패턴으로 만든다.
  - 공통 컴포넌트(계좌 카드, 숫자 카운터, 막대, 라인, 와플 그리드, 말풍선, 헤드라인 카드, 번호 타이틀)를 먼저 만들고 장면마다 재사용한다. 장면마다 새로 그리지 않는다.
  - 전체 렌더 전에 스토리보드(장면별 still)로 검수해서, 전체 렌더를 여러 번 하지 않는다.
- **렌더 명령:** `npx remotion render <컴포지션ID> out/final_1080p.mp4 --codec=h264 --crf=18`
- 수정할 때마다 `CHANGELOG.md`에 버전, 날짜, 바뀐 장면을 기록한다.

## 3. 디자인 시스템 (1080p 기준)

### 3-1. 색 (의미 고정)
| 의미 | 색 | HEX |
|---|---|---|
| 기본 배경 | 크림 종이 | #F2EBDD |
| 위기 장면 배경 (S04~S08) | 다크 네이비 | #14213D |
| 글자·선 | 잉크 | #1E1E1E (네이비 배경에서는 #F7F3EA) |
| 수익·상승 | 빨강 | #E63B2E |
| 손실·하락 | 파랑 | #2D6CDF |
| 핵심 강조 (한 화면에 한 곳만) | 노랑 형광펜 | #FFD400 |
| 비교 대상·보조 정보 | 웜 그레이 | #9A968E |
| 사연자의 계좌·종목(MDB) | 잉크 테두리 + 크림 채움 카드 | 영상 내내 같은 모양 |

### 3-2. 크기와 위치
| 요소 | 크기 |
|---|---|
| 핵심 숫자 (예: -2,000만 원, 58%) | 160–220px, Noto Sans KR 900 |
| 장면 헤드라인·번호 타이틀 | 72–88px, Noto Serif KR 900 |
| 라벨 | 36–44px, Noto Sans KR 700 |
| 출처·"개념도" 캡션 | 24px, 웜 그레이 |
| 화면의 모든 글자 | 최소 28px |

- 바깥 여백 96px. 그래픽은 세로 120~800px 영역에만 놓는다.
- 핵심 숫자나 핵심 그래픽은 화면 중앙 또는 중앙에서 약간 위에 두어 시선이 바로 가게 한다.
- 비교는 항상 왼쪽 = 나쁜 쪽(몰빵), 오른쪽 = 좋은 쪽(분산)으로 일관되게 배치한다.

### 3-3. 자막
- 화면 하단 중앙, 아래 여백 72px, 최대 너비 1500px, 46px Noto Sans KR 700.
- 크림 배경: 잉크 글자 + 크림 띠(불투명도 92%, 모서리 12px). 네이비 배경: 밝은 글자 + 네이비 띠(불투명도 85%).
- SRT의 줄바꿈을 그대로 쓴다. 자막 하나에 한 문장만 보이고, 자막 사이에 빈 화면이 없다.
- 등장·퇴장은 4프레임 페이드.

### 3-4. 모션
- 등장 12–18프레임, 퇴장 8–10프레임, spring 기반 ease-out. 과한 바운스 금지.
- 여러 요소는 4–6프레임 간격으로 순차 등장한다.
- 장면마다 1.00 → 1.03 정도로 천천히 줌인한다.
- 핵심 단어·숫자는 노랑 형광펜이 왼쪽→오른쪽으로 10프레임 동안 그어진다.
- 선과 차트는 `stroke-dashoffset`으로 그려지는 애니메이션을 쓴다.
- 금액과 %는 20–30프레임 동안 카운트업·카운트다운한다.
- 장면 전환은 찢어진 종이 와이프(가벼운 폴리곤 clip-path)와 컷을 번갈아 쓴다.
- 각 요소는 그 내용을 말하는 자막이 시작될 때 등장한다.

## 5. 장면 구성 (자막 번호 기준, 고지 카드 포함 30장면)

각 장면의 **모든 요소는 해당 자막의 말에서 나온다.** "연결 근거" 칸은 그 요소가 왜 나오는지를 적은 것으로, 스토리보드 검수 때 그대로 확인한다.

| 장면 | 자막 | 배경 | 모션그래픽 연출 | 화면 텍스트 | 연결 근거 |
|---|---|---|---|---|---|
| S01 | 1–2 | 크림 | 선으로 그린 스마트폰 안 검색창에 "AI 관련주"가 타이핑되고 결과 카드 "몽고디비 MDB"가 올라온다. 자막 2에서 카드 아래 체크 3개가 순서대로 그려진다 | AI 관련주 / 몽고디비 MDB / 전망 ✓ 실적 ✓ 상승세 ✓ | 종목을 알게 된 경위, 고른 이유 3가지 |
| S02 | 3 | 크림 | **사연자의 계좌 카드**가 등장한다. 카드 안 비중 막대가 MDB 한 종목 색으로 100% 꽉 찬다 | 내 계좌 7,000만 원 / MDB 100% / 몰빵(노랑) | 전 재산을 한 종목에 넣음 |
| S03 | 4–5 | 크림 | 계좌 카드의 평가손익이 0 → +1,000만 원(빨강)으로 오르고 작은 상승선이 그려진다(개념도). 자막 5에서 위쪽에 "전고점" 점선과 위로 향하는 점선 화살표가 나타난다 | +1,000만 원 / 전고점 | 수익, 더 오를 것 같은 기대 |
| S04 | 6 | 크림 → 네이비 | 화면의 색이 빠지며 찢어진 종이 와이프로 네이비 배경이 된다 | — | 반전 예고 |
| S05 | 7 | 네이비 | 같은 계좌 카드의 숫자가 +1,000만 → -2,000만 원으로 내려가며 빨강이 파랑으로 바뀌고, 카드가 3프레임 흔들린다 | -2,000만 원 | 계좌에 찍힌 손실 |

## 6. 작업 순서

1. 입력 파일을 확인한다. SRT나 TXT가 없으면 멈추고 알린다.
2. `./video`에 Remotion 프로젝트를 만들고(이미 있으면 재사용) Agent Skills를 설치한다.
3. SRT를 파싱해 `subtitles.ts`를 만든다. 자막 개수가 96개인지, 고지 카드 6초를 반영한 전체 길이가 약 9분 8초인지 콘솔에 출력해 확인한다.
4. 디자인 시스템과 공통 컴포넌트를 만들고, S01–S30을 구현한다.
5. **스토리보드를 만들고 여기서 멈춘다.**
   - 장면마다 모든 요소가 다 나온 시점(장면 끝 10프레임 전)의 still을 `out/storyboard/S01.png` ~ `S30.png`로 렌더한다. 한 장면 안에서 그림이 크게 바뀌는 장면(S14, S16~S19, S25~S29)은 자막 단위로 1장씩 더 만든다(`S25-66.png`처럼).
   - `out/storyboard/index.html`을 만든다. 장면마다 이미지, 장면 번호, 자막 번호, 자막 원문, "연결 근거" 한 줄을 카드로 보여 준다.
   - 사용자에게 보여 주기 전에 still을 직접 열어 아래 검수표를 통과시킨다.
   - 그다음 index.html 경로와 장면별 한 줄 요약을 보고하고, **사용자의 승인이나 수정 지시를 기다린다. 승인 전에는 전체 렌더를 하지 않는다.**
6. 사용자가 고칠 장면을 말하면 그 장면만 고치고, 그 장면의 still만 다시 만들어 보여 준다.
7. 승인되면 `out/final_1080p.mp4`를 렌더한다.
8. **결과 보고:** 출력 경로, 영상 길이, 렌더에 걸린 시간, 사용자가 채워야 할 값을 알린다.
